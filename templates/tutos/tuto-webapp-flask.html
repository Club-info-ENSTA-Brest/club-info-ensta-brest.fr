Tuto : Faire sa première WebApp avec Flask

Flask · SQLite · HTMX · HTML/CSS

Construire une TodoList dynamique from scratch

Dans ce tuto, on construit une petite WebApp complète : une interface HTML/CSS, un backend Flask, une base SQLite et des interactions dynamiques avec HTMX. Le but n'est pas de tout connaître par cœur, mais de comprendre comment les briques s'assemblent pour pouvoir ensuite faire évoluer son projet proprement, avec ou sans IA.

TL;DR

Une WebApp, c'est une interface qui envoie des requêtes à un backend. Le backend lit ou modifie des données, puis renvoie une réponse. Ici, HTMX nous permet de remplacer des morceaux de page sans écrire de JavaScript compliqué.

L'idée du projet

On veut créer une TodoList. C'est volontairement simple : une tâche a un titre, une description, une date limite et un niveau d'importance. Pourtant, ce petit projet contient déjà presque tous les concepts d'une vraie WebApp.

Utilisateur → HTML/CSS → HTMX → Flask → SQLite → Flask → HTML/CSS

L'utilisateur clique, écrit ou cherche quelque chose dans l'interface [Utilisateur → HTML]. HTMX transforme cette action en requête vers Flask [HTML → HTMX → Flask]. Le backend Flask reçoit la requête, l'interprète, puis appelle une fonction Python qui lit ou modifie SQLite [Flask → SQLite → Flask]. Enfin, Flask renvoie du HTML à afficher dans la page [Flask → HTML].

Avant-propos — Le vrai objectif : piloter le projet, pas juste copier ou générer du code

Aujourd'hui, l'IA peut écrire beaucoup de code. Mais si on lui demande simplement « fais-moi une WebApp », elle risque de produire un bloc opaque : ça semble fonctionner à première vue, mais c'est difficile à modifier et pas forcément aligné avec ce qu'on voulait vraiment.

Idée importante

L'IA est le junior dev le plus rapide et le plus talentueux du monde ; mais elle n'est pas l'architecte de votre projet.

Votre rôle est de définir le fonctionnement, les données, les pages, les composants, les routes et les interactions. Ensuite, l'IA peut accélérer l'implémentation.

Un mauvais prompt serait :

Fais-moi une TodoList complète avec Flask.

Un meilleur prompt serait :

Dans mon app Flask, j'ai une table tasks(id, title, description, due_date, importance).
Ajoute une route DELETE /tasks/<id> qui supprime la tâche puis renvoie une réponse vide pour HTMX.

Le second prompt marche mieux parce qu'il donne un cadre : l'architecture existe déjà, l'IA doit seulement ajouter une brique cohérente.

1. Installer les dépendances

Il faut d'abord installer ce que l'on va utiliser.

Python :

https://www.python.org/downloads/

→ Pour les GOATS sur Linux ou macOS, je vous laisse installer ça avec votre package manager. Si vous êtes sur Mac et que vous ne savez pas ce que c'est, renseignez-vous sur Homebrew.

Ensuite, il faut installer les librairies Python. Pour faire ça proprement, la meilleure méthode est de créer un virtual environment : un environnement isolé pour les dépendances du projet.

Ouvrez un terminal ou une invite de commande (CMD ou PowerShell sur Windows), puis créez votre environnement virtuel :

cd [chemin sur le disque vers votre projet]
python -m venv .venv

Pour l'activer, il faut ensuite exécuter la commande adaptée à votre système depuis le répertoire du projet :

.venv\Scripts\activate      # Windows
source .venv/bin/activate   # Linux et macOS

Une fois cela fait, on peut installer les librairies. La liste des librairies est écrite dans un fichier requirements.txt. Pour les installer, exécutez : 

pip install -r requirements.txt

2. Structure des fichiers pour Flask

Flask respecte une architecture de projet assez simple.

Tout projet Flask possède un backend : un fichier Python qui reçoit les requêtes du navigateur et décide quoi renvoyer. Ici, ce fichier s'appelle backend.py.

Les pages HTML du site sont rangées dans un dossier templates.

Les scripts, les feuilles de style CSS, les images, les vidéos et les autres fichiers publics sont rangés dans le dossier static.

Une structure minimale de projet pourrait ressembler à :

projet-webapp-flask/
├── backend.py
├── requirements.txt
├── static/
│   ├── style.css
│   └── script.js
└── templates/
    └── home.html

Dans notre cas, on aura plutôt quelque chose qui ressemble à ça :

atelier-todolist/
├── backend.py
├── database.db              # généré automatiquement
├── requirements.txt
├── static/
│   ├── style.css
│   └── script.js
└── templates/
    ├── home.html
    ├── _task.html
    └── _tasks.html

3. Les routes Flask

Flask reçoit les requêtes du navigateur. Chaque route correspond à une URL et à une action de l'application.

Route Rôle
GET / Afficher la page principale avec les tâches.
POST /add Ajouter une tâche et renvoyer sa card HTML.
GET /search?q=... Chercher dans les tâches et renvoyer les cards correspondantes.
GET /sort?by=... Trier les tâches par date, importance ou création.
DELETE /tasks/<id> Supprimer une tâche.

Une route Flask de base qui permet de retourner la page home.html s'écrit :

@app.route("/")
def home():
    return render_template("home.html")

Le grand avantage de Flask est qu'il permet aussi de passer des informations à la page Web. Pour cela, on peut ajouter des données lorsqu'on retourne la page. Par exemple, si une fonction get_tasks() récupère les tâches sous forme de liste de dictionnaires, on peut faire : 

@app.route("/")
def home():
    tasks = get_tasks()
    return render_template("home.html", tasks=tasks)

On pourra ensuite accéder à la variable tasks directement dans notre code HTML.

4. Construire et concevoir une interface en HTML et CSS

Avant de coder, on dessine l'interface. On décide où placer le menu, la barre de recherche, la liste des tâches et le formulaire d'ajout. Ensuite, on imagine comment ranger ces éléments dans une interface construite à partir de blocs avec des tailles et des règles de positionnement : en haut, en bas, à gauche, en bas à droite, etc. Ces blocs sont des div, et les règles de positionnement sont souvent définies avec flex.

Pour simplifier l'écriture de votre WebApp, vous pouvez vous inspirer du code d'exemple et utiliser des classes qui correspondent à des règles CSS déjà écrites.

Méthode

Pour créer réellement un projet à partir de zéro, ne commencez pas par écrire tout le CSS. Commencez par placer les blocs, d'abord sur papier, puis écrivez seulement le CSS nécessaire pour définir les lignes, colonnes, panneaux, boutons et inputs. Une fois la structure claire, rendre la page jolie devient beaucoup plus simple.

Ici, vous avez à disposition des styles déjà écrits. Voici quelques classes utiles :

Classe Utilité
.container-rowPlace les enfants horizontalement.
.container-columnPlace les enfants verticalement.
.centerCentre horizontalement et verticalement.
.w-80, .h-100Contrôle la largeur et la hauteur.
.pannelCrée un panneau stylé.
.btnCrée un bouton cohérent avec le thème.
.inputStyle les champs du formulaire.
.taskReprésente une tâche sous forme de card.
.overlay, .modalAffiche une popup au-dessus de la page.

Pour donner une classe à une div, on écrit par exemple :

<div class="container-column center w-20 h-100">
    ...
</div>

Pour mieux comprendre la structure, je vous conseille de regarder comment l'exemple est écrit.

Après avoir organisé ces blocs, on peut ajouter du texte, des images, des liens, des boutons, etc.

Après avoir conçu et implémenté la page en HTML et CSS, il faut pouvoir utiliser les données passées avec return render_template("home.html", tasks=tasks).

Pour cela, on écrit des expressions Jinja directement dans le HTML :

<p class="big-text">{{ '{{ tasks[0].title }}' }}</p>

On peut faire quelque chose d'encore plus puissant : des boucles.

{% raw %}{% for task in tasks %}
    <p class="big-text">{{ task.title }}</p>
{% endfor %}{% endraw %}

5. La base de données

Pour ne pas passer tout l'atelier sur SQLite, on peut fournir une petite librairie Python déjà prête. L'objectif est de comprendre quand on utilise la base, pas forcément d'écrire tout le boilerplate à la main dès le début.

La base de données utilisée ici a la forme suivante :

CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    description TEXT DEFAULT '',
    due_date TEXT DEFAULT '',
    importance TEXT DEFAULT 'normal',
    done INTEGER DEFAULT 0,
    created_at TEXT NOT NULL
)

Les fonctions utiles peuvent être exposées comme ça :

from todolist_kit import init_db, get_tasks, create_task, delete_task, search_tasks

À retenir

Une base de données sert à garder les informations même après un refresh ou un redémarrage. Ici, toutes les cards affichées viennent de SQLite.

6. Les fragments Jinja

Au lieu de répéter le HTML d'une tâche partout et de se retrouver avec du code spaghetti très long, on peut créer un fragment de code HTML dans un fichier séparé : _task.html. 

<div class="task" id="task-{{ '{{ task.id }}' }}">
    <button
        class="icon-btn task-delete-btn"
        hx-delete="/tasks/{{ '{{ task.id }}' }}"
        hx-target="#task-{{ '{{ task.id }}' }}"
        hx-swap="outerHTML"
    >🗑</button>

    <p class="title">{{ '{{ task.title }}' }}</p>
    <p>{{ '{{ task.description }}' }}</p>
</div>

Puis on peut afficher toute la liste avec _tasks.html, qui utilise le composant _task.html : 

{% raw %}{% for task in tasks %}
    {% include "_task.html" %}
{% else %}
    <p>Aucune tâche.</p>
{% endfor %}{% endraw %}

7. HTMX : connecter le front au backend sans tout recharger à chaque fois

À ce stade, on a quelque chose qui fonctionne presque. Le problème, c'est que pour mettre à jour les données, on est obligé de rafraîchir toute la page.

HTMX permet d'envoyer une requête HTTP depuis un élément HTML et de placer la réponse directement dans la page, sans passer par du JavaScript complexe.

Pour envoyer un ensemble de données, par exemple pour ajouter une tâche, on se sert d'un form : une sorte de réponse à un questionnaire — d'où le nom de Google Forms, par exemple. 

<form
    hx-post="/add"
    hx-target="#task-list"
    hx-swap="afterbegin"
>
    ...
</form>

Traduction :

  • hx-post="/add" : envoie le formulaire à Flask.
  • hx-target="#task-list" : la réponse sera placée dans la liste des tâches.
  • hx-swap="afterbegin" : la nouvelle card est ajoutée au début.

Chaque élément d'un form peut être de nature différente : input, select, textarea, etc. 

<input
    name="q"
    hx-get="/search"
    hx-trigger="input changed delay:200ms"
    hx-target="#task-list"
    hx-swap="innerHTML"
>

Ici, chaque fois qu'on tape dans la barre de recherche, HTMX demande à Flask les résultats correspondants et remplace la liste.

8. Ajouter, chercher, trier, supprimer

Les fonctionnalités importantes suivent toutes le même modèle :

Action HTML → Route Flask → Fonction DB → Fragment HTML

Exemple : supprimer une tâche.

@app.route("/tasks/<int:task_id>", methods=["DELETE"])
def delete_task_route(task_id):
    delete_task_from_db(task_id)
    return "", 200

Et côté HTML :

<button
    hx-delete="/tasks/{{ '{{ task.id }}' }}"
    hx-target="#task-{{ '{{ task.id }}' }}"
    hx-swap="outerHTML"
>🗑</button>

À retenir

Une feature WebApp, c'est souvent : un bouton ou un formulaire, une route Flask, une fonction qui modifie les données, puis un fragment HTML renvoyé.

Utilisation de l'IA

Après avoir correctement défini sa base de données et écrit au moins une méthode proprement, l'ajout d'autres types d'actions peut se faire sans trop de risques en demandant à une IA de rajouter la feature souhaitée en s'inspirant du code déjà écrit.

9. Et après ? Aller plus loin

Cette app est volontairement locale et pédagogique. Elle ne gère pas les comptes utilisateurs, les mots de passe ou les permissions. C'est une bonne chose pour commencer : on apprend les bases sans ouvrir directement les problèmes de sécurité d'une vraie app publique.

Attention

Ne mettez pas en ligne une app avec des données sensibles sans comprendre l'authentification, les permissions, les variables d'environnement, les sessions et la sécurité Web.

Idées d'améliorations raisonnables :

  • Ajouter un bouton pour marquer une tâche comme terminée, au lieu de simplement la supprimer.
  • Ajouter des filtres : urgent, aujourd'hui, terminé.
  • Ajouter un thème clair/sombre.

Conclusion

Ce tuto ne cherche pas à faire de vous des experts Flask, SQLite, HTMX et CSS en une heure. Il cherche à vous donner un modèle mental solide : une WebApp est un ensemble de briques qui communiquent. Si vous savez dessiner ces briques, nommer les données et définir les routes, vous pouvez construire des projets beaucoup plus ambitieux sans perdre le contrôle.

Phrase à garder

Ne demandez pas à l'IA de créer votre projet à votre place. Construisez l'architecture, puis utilisez l'IA pour accélérer l'implémentation de briques précises. Plus on donne à l'IA des ordres précis avec des exemples, moins on lui laisse la liberté de faire quelque chose que l'on ne souhaite pas.
