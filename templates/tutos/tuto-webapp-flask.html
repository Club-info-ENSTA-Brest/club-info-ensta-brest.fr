Tuto : Faire sa première WebApp avec Flask

Flask · SQLite · HTMX · HTML/CSS

Construire une TodoList dynamique from scratch

Dans ce tuto, on construit une petite WebApp complète : une interface HTML/CSS, un backend Flask, une base SQLite et des interactions dynamiques avec HTMX. Le but n'est pas de tout connaître par cœur, mais de comprendre comment les briques s'assemblent pour pouvoir ensuite faire évoluer son projet proprement, avec ou sans IA.

TL;DR

Une WebApp, c'est une interface qui envoie des requêtes à un backend. Le backend lit ou modifie des données, puis renvoie une réponse. Ici, HTMX nous permet de remplacer des morceaux de page sans écrire de JavaScript compliqué.

Sommaire

  1. Comprendre l'architecture générale
  2. Préparer le projet Flask
  3. Créer une base SQLite pour stocker les tâches
  4. Afficher les tâches dans des cards HTML
  5. Ajouter une tâche avec un formulaire et HTMX
  6. Chercher, trier et supprimer des tâches
  7. Comment utiliser l'IA proprement pour continuer le projet

1. L'idée du projet

On veut créer une TodoList. C'est volontairement simple : une tâche a un titre, une description, une date limite, une importance et un état. Pourtant, ce petit projet contient déjà presque tous les concepts d'une vraie WebApp.

Utilisateur → HTML/CSS → HTMX → Flask → SQLite

L'utilisateur clique, écrit ou cherche quelque chose dans l'interface. HTMX transforme cette action en requête HTTP. Flask reçoit la requête, appelle une fonction Python, lit ou modifie SQLite, puis renvoie du HTML à remettre dans la page.

2. Le vrai objectif : piloter le projet, pas juste copier un tuto

Aujourd'hui, l'IA peut écrire beaucoup de code. Mais si on lui demande simplement "fais-moi une WebApp", elle risque de produire un bloc opaque, difficile à modifier et pas forcément aligné avec ce qu'on voulait vraiment.

Idée importante

L'IA est le junior dev le plus rapide du monde, pas l'architecte de votre projet. Votre rôle est de définir les données, les pages, les composants, les routes et les interactions. Ensuite, l'IA peut accélérer l'implémentation.

Un mauvais prompt serait :

Fais-moi une TodoList complète avec Flask.

Un meilleur prompt serait :

Dans mon app Flask, j'ai une table tasks(id, title, description, due_date, importance).
Ajoute une route DELETE /tasks/<id> qui supprime la tâche puis renvoie une réponse vide pour HTMX.

Le second prompt marche mieux parce qu'il donne un cadre : l'architecture existe déjà, l'IA doit seulement ajouter une brique cohérente.

4. La base de données

Pour ne pas passer tout l'atelier sur SQLite, on peut fournir une petite librairie Python déjà prête. L'objectif est de comprendre quand on utilise la base, pas forcément d'écrire tout le boilerplate à la main dès le début. 

CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    description TEXT DEFAULT '',
    due_date TEXT DEFAULT '',
    importance TEXT DEFAULT 'normal',
    done INTEGER DEFAULT 0,
    created_at TEXT NOT NULL
)

Les fonctions utiles peuvent être exposées comme ça :

from todolist_kit import init_db, get_tasks, create_task, delete_task, search_tasks

À retenir

Une base de données sert à garder les informations même après un refresh ou un redémarrage. Ici, toutes les cards affichées viennent de SQLite.

5. Les routes Flask

Flask reçoit les requêtes du navigateur. Chaque route correspond à une action de l'application.

Route Rôle
GET / Afficher la page principale avec les tâches.
POST /add Ajouter une tâche et renvoyer sa card HTML.
GET /search?q=... Chercher dans les tâches et renvoyer les cards correspondantes.
GET /sort?by=... Trier les tâches par date, importance ou création.
DELETE /tasks/<id> Supprimer une tâche. 
@app.route("/")
def home():
    tasks = get_tasks()
    return render_template("home.html", tasks=tasks)

6. Penser l'interface en blocs

Avant de coder, on dessine l'interface. On décide où mettre le menu, la barre de recherche, la liste des tâches et le formulaire d'ajout. Ensuite, on assemble des classes CSS déjà écrites.

Méthode

Ne commencez pas par écrire du CSS. Commencez par placer les blocs : lignes, colonnes, panneaux, boutons, inputs. Une fois la structure claire, le style devient beaucoup plus simple.

Classe Utilité
.container-rowPlace les enfants horizontalement.
.container-columnPlace les enfants verticalement.
.centerCentre horizontalement et verticalement.
.w-80, .h-100Contrôle largeur et hauteur.
.pannelCrée un panneau stylé.
.btnCrée un bouton cohérent avec le thème.
.inputStyle les champs du formulaire.
.taskCard représentant une tâche.
.overlay, .modalPopup au-dessus de la page.

7. Les fragments Jinja

Au lieu de répéter le HTML d'une task partout, on crée un composant réutilisable : _task.html. 

<div class="task" id="task-{{ '{{ task.id }}' }}">
    <button
        class="icon-btn task-delete-btn"
        hx-delete="/tasks/{{ '{{ task.id }}' }}"
        hx-target="#task-{{ '{{ task.id }}' }}"
        hx-swap="outerHTML"
    >🗑</button>

    <p class="title">{{ '{{ task.title }}' }}</p>
    <p>{{ '{{ task.description }}' }}</p>
</div>

Puis on peut afficher toute la liste avec _tasks.html : 

{% raw %}{% for task in tasks %}
    {% include "_task.html" %}
{% else %}
    <p>Aucune task.</p>
{% endfor %}{% endraw %}

8. HTMX : connecter le front au backend

HTMX permet d'envoyer une requête HTTP depuis un élément HTML et de placer la réponse directement dans la page. Pas besoin d'écrire du JavaScript complexe pour commencer. 

<form
    hx-post="/add"
    hx-target="#task-list"
    hx-swap="afterbegin"
>
    ...
</form>

Traduction :

  • hx-post="/add" : envoie le formulaire à Flask.
  • hx-target="#task-list" : la réponse sera placée dans la liste des tâches.
  • hx-swap="afterbegin" : la nouvelle card est ajoutée au début.
<input
    name="q"
    hx-get="/search"
    hx-trigger="input changed delay:200ms"
    hx-target="#task-list"
    hx-swap="innerHTML"
>

Ici, chaque fois qu'on tape dans la barre de recherche, HTMX demande à Flask les résultats correspondants et remplace la liste.

9. Ajouter, chercher, trier, supprimer

Les fonctionnalités importantes suivent toutes le même modèle :

Action HTML → Route Flask → Fonction DB → Fragment HTML

Exemple : supprimer une tâche.

@app.route("/tasks/<int:task_id>", methods=["DELETE"])
def delete_task(task_id):
    delete_task_from_db(task_id)
    return "", 200

Et côté HTML :

<button
    hx-delete="/tasks/{{ '{{ task.id }}' }}"
    hx-target="#task-{{ '{{ task.id }}' }}"
    hx-swap="outerHTML"
>🗑</button>

À retenir

Une feature WebApp, c'est souvent : un bouton ou formulaire, une route Flask, une fonction qui modifie les données, puis un fragment HTML renvoyé.

10. Et après ?

Cette app est volontairement locale et pédagogique. Elle ne gère pas les comptes utilisateurs, les mots de passe ou les permissions. C'est une bonne chose pour commencer : on apprend les bases sans ouvrir directement les problèmes de sécurité d'une vraie app publique.

Attention

Ne mettez pas en ligne une app avec des données sensibles sans comprendre l'authentification, les permissions, les variables d'environnement, les sessions et la sécurité Web.

Idées d'améliorations raisonnables :

  • Ajouter un bouton pour marquer une tâche comme terminée.
  • Ajouter des filtres : urgent, aujourd'hui, terminé.
  • Ajouter un thème clair/sombre.
  • Créer une page de documentation des classes CSS.
  • Demander à une IA d'ajouter une feature précise dans cette architecture.

Conclusion

Ce tuto ne cherche pas à faire de vous des experts Flask, SQLite, HTMX et CSS en une heure. Il cherche à vous donner un modèle mental solide : une WebApp est un ensemble de briques qui communiquent. Si vous savez dessiner ces briques, nommer les données et définir les routes, vous pouvez construire des projets beaucoup plus ambitieux sans perdre le contrôle.

Phrase à garder

Ne demandez pas à l'IA de créer votre projet à votre place. Construisez l'architecture, puis utilisez l'IA pour accélérer l'implémentation de briques précises.
